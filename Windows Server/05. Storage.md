# 개요

이번 시간에는 Storage에 대해서 짧게 정리하고 넘어가려 합니다. 하드웨어 단 보다는 OS쪽에 중점을 두어 설명을 할 예정입니다.

서버에 스토리지를 붙여서 사용하는 규격인 `SCSI`(Small Computer System Interface)가 처음 등장을하게 되었고,  
이에 대하여 고속으로 데이터를 전송할 수 있는 `FC`(파이버 채널)이 나오게 되며, FC를 사용하는 스토리지를 `SAN` 스토리지라고 부르게 됩니다. 
fc 케이블은 일반적인 케이블보다 값이 비싸며 FC네트워크 환경이 아닌 `IP 환경`에서 사용하기 위해 `ISCSI` 가 나오게 됩니다.

그렇다면 우리가 평소에 IP 네트워크 환경에서 사용하는 NAS는 위와 같은 스토리지일까요? 정답은 전혀 다른 프로토콜을 사용하는 스토리지입니다.  
ISCSI는 `블록 스토리지`이며, NAS와 같은 SMB 및 NFS는 `파일 스토리지` 입니다.
* `블록 스토리지`: OS에서 로컬 디스크처럼 인식하여 볼륨을 구성하여 드라이브로 사용
* `파일 스토리지`: 공유 폴더에 파일 단위로 접근하여 해당 폴더를 사용

* 일반적으로 Windows에서 SAN 스토리지를 중요하게 다루는 이유는 Failover Cluster에서 사용하는 `Shared Disk` 때문입니다.

### Target Server에서 `UniqueId` 확인 방법
```powershell
Get-CimInstance `
    -Namespace "root/cimv2/Storage/iSCSITarget" `
    -ClassName "MSISCSITARGET_StorageVolume" |
Select-Object `
    @{Name="VolumeIdentifier"; Expression={$_.Name}},
    @{Name="IdentifierFormat"; Expression={$_.NameFormat}},
    @{Name="IdentifierNamespace"; Expression={$_.NameNamespace}},
    @{Name="DevicePath"; Expression={$_.MSDevicePath}} |
Format-List
```
* 추후 위 명령어로 `VolumeIdentifier`를 확인 가능하며, Node 쪽에서 `UniqueId`를 확인하면 됩니다.  

```powershell

VolumeIdentifier    : 60003FF44DC75ADCBB1C6269992FE83A

DevicePath          : C:\data\FCI-D.vhdx
```
