### 2. 도메인 Member Server의 식별과 보안 채널
```
장치가 도메인에 가입하면 컴퓨터 계정이 생성됩니다. 도메인에 가입된 후, 장치는 해당 계정의 암호를 사용하여 재시작할 때마다 도메인 컨트롤러와 보안 채널을 설정합니다. 이 보안 채널은 NTLM 패스스루 인증 및 LSA SID/이름 조회와 같은 작업을 수행하는 데 사용됩니다. 
```
[Reference] [https://learn.microsoft.com/en-us/previous-versions/windows/it-pro/windows-10/security/threat-protection/security-policy-settings/domain-member-digitally-encrypt-secure-channel-data-when-possible](https://learn.microsoft.com/en-us/previous-versions/windows/it-pro/windows-10/security/threat-protection/security-policy-settings/domain-member-digitally-encrypt-secure-channel-data-when-possible)

* 우선 기본적으로 AD는 서버를 알아볼 때, `개체 SID` 값과 `개체 비밀번호`를 통하여 해당 서버를 인식합니다.  

<br>

_아래 예시는 AD에 탈퇴하지 않고 VM을 삭제한 후, 같은 이름으로 Domain에 가입하는 상황입니다._  
위와 같은 상황일 때, AD는 멤버 서버가 새로운 멤버 서버로 바뀌었다는 것을 인식할까요?  
```
Get-ADComputer [서버명] -Properties pwdLastSet, lastLogonTimestamp, whenChanged
```

* 위와 같이 AD 재가입 시, 비밀번호 변경을 통하여 해당 개체가 다른 멤버 멤버서버로 변경되었다는 것을 인식하고 보안 채널을 설정하게 됩니다.  
* 여기서 중요한 점은 DC에서 Computer Object를 삭제하는 것이 아닌 이상 `SID`와 `ObjectGUID` 값이 변경되지 않습니다.  
* _whenChanged는 AD 재가입 시점입니다._

## 2. Local SID 확인  

* AD에서 개체를 관리할 때만 SID 값을 할당 받는게 아니라, Local Machine 자체에도 SID 값이 있다.  
* Sysprep을 제대로 하지 않고, 이미지를 만들게 되면 이 SID값이 중복되게 되는데 `Windows 11 24h2 8월`부터는 RDP 혹은 SMB에서 인증이 정상적으로 되지 않는 현상이 종종 발생하여 확인이 필요하다.  
* Link:  https://support.microsoft.com/en-us/servicing/os/windows/docs/2025/10/kerberos-and-ntlm-authentication-failures-due-to-duplicate-sids?preview=true  

```powershell
get-localuser | % {$_.SID}
```

## 3. Secure Channel 검증

```powershell
PS C:\Users\corpadmin> Test-ComputerSecureChannel -Verbose
자세한 정보 표시: 대상 "WebSvr22-01"에서 "Test-ComputerSecureChannel" 작업을 수행합니다.
True
자세한 정보 표시: 로컬 컴퓨터와 Corp.com 도메인 간의 보안 채널이 정상적으로 작동 중입니다.

PS C:\Users\corpadmin> nltest /sc_query:Corp.com
플래그: 10 HAS_IP
트러스트된 DC 이름 \\CorpAD16-01.Corp.com
트러스트된 DC 연결 상태 Status = 0 0x0 NERR_Success
명령을 완료했습니다.

PS C:\Users\corpadmin> nltest /sc_verify:Corp.com
플래그: 90 HAS_IP
트러스트된 DC 이름 \\CorpAD16-01.Corp.com
트러스트된 DC 연결 상태 Status = 0 0x0 NERR_Success
트러스트 검증 Status = 0 0x0 NERR_Success
명령을 완료했습니다.

PS C:\Users\corpadmin> netdom verify WebSvr22-01 /domain:Corp.com
WebSvr22-01에서 CORP.COM 도메인으로의 보안 채널을 검증했습니다. \\CORPAD16-01.CORP.COM 시스템과
연결됩니다.

명령을 완료했습니다.
```  
* `Test-ComputerSecureChannel`: Secure Channel 정상 여부 확인
    * 만약 __False__ 일 경우, `Test-ComputerSecureChannel -Repair`로 다시 보안 채널을 설정합니다.
    * Link: https://learn.microsoft.com/ko-kr/powershell/module/microsoft.powershell.management/test-computersecurechannel?view=powershell-5.1
* `nltest /sc_query`: 현재 Secure Channel/DC 정보 조회
* `nltest /sc_verify`: Secure Channel 실제 검증
* `netdom verify`: 컴퓨터 ↔ 도메인 Secure Channel 검증
