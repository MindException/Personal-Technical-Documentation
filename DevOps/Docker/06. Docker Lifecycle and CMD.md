## 1. Container LifeCycle

도커 이미지를 레지스트리로부터 가져오게 되어 실행시켰을 때, 컨테이너는 아래의 LifeCycle로 운영되게 됩니다.  
여기서 빠르게 자주 쓰는 명령어만 알아보겠습니다.

### 1. 컨테이너 생성 및 시작
```bash
# Run (생성 + 시작)
$docker run [OPTIONS] [IMAGE TAG OR DIGEST] [COMMAND] [ARG]

# 생성
$docker create [OPTIONS] [IMAGE TAG OR DIGEST] [COMMAND] [ARG]

# 시작
$docker start [Container Name]
```

|옵션|설명|
|:---:|:---|
|-d, --detach| 백그라운드 모드로 실행 / _start 명령어는 기본 값이 백그라운드로 동작_|
|-p, --publish| 호스트 서버와 컨테이너 포트 연결(`[호스트port]:[컨테이너port]`)|
|-v, --voloume| 호스트 파일 및 폴더를 컨테이너에 마운트 (`[호스트 경로 혹은 파일]:[컨테이너 경로 혹은 파일]`) |
|-e, --env|컨테이너 내에서 사용할 환경 변수 설정 |
|--name| 컨테이너 이름 설정|
|--hostname|컨테이너 내부에서 인식하는 hostname 지정|
|--rm| 프로세스 종료 시, 컨테이너 자동 제거|
|-it| 컨테이너 내에 터미널 STDIN 오픈|
|-link|(Legacy) 컨테이너 연결[컨테이너:별칭]|

<br>

```bash
# 예시1 Tomcat
$docker run -d -p 80:8080 --name tc consol/tomcat-7.0

# 예시2 MS SQL
$docker run -e "ACCEPT_EULA=Y" -e "MSSQL_SA_PASSWORD=<password>" -e "MSSQL_PID=Evaluation" -p 1433:1433  --name sql2025 --hostname sql2025 -d mcr.microsoft.com/mssql/server:2025-latest
```

<br>

### 2. 컨테이너 상태 조회

```bash
$docker ps -a
```
* 컨테이너 상태를 조회하는데에는 다른 명령어들도 있지만 위 명령어만으로도 충분합니다.
* `-a`: 위 옵션을 추가하여야 실행 중이지 않은 컨테이너들까지 모두 출력됩니다.  
* `--no-trunc`: 명령어 결과 출력 시에 해당 옵션을 사용하게 되면 결과값의 문자열이 짤리지 않고 전부 출력됩니다.  

```bash
$docker ps -a

0aa02d91b069   mcr.microsoft.com/mssql/server:2022-latest   "/opt/mssql/bin/laun…"   6 weeks ago     Exited (137) 4 minutes ago                                             elastic_bassi
c24a820dbba3   57e903d5641d                                 "/docker-entrypoint.…"   6 weeks ago     Up 6 weeks                   0.0.0.0:8123->80/tcp, [::]:8123->80/tcp   tc1
```
* 일반적으로 컨테이너만 생성되었으면 STATUS가  `Created`  
컨테이너가 종료되었으면 `Excited`이며 실행 중이거나 pause하였을 경우에는 `UP`으로 표기 됩니다.

### 3. 컨테이너 중지 및 삭제

```bash
# 중지 및 삭제
$docker stop [컨테이너명]
$docker rm [컨테이너명]

# 강제 중지 후, 삭제
$docker rm -f [컨테이너명]
```
* 일반적인 컨테이너 중지는 위 명령어를 따르게 됩니다.  

<br>

```bash
# systerm을 보내고 
$docker stop -t 0 [컨테이너명]

# 컨테이너 ID 값으로 전체 삭제
$docker stop $(docker ps -a -q)

# 이미지 삭제
$docker rmi [이미지명]
```
* 일반적으로 중지 명령어를 내리면 linux는 `sigterm`이 발생하여 종료되는데 시간이 소요됩니다.  
* 이 때 `-t` `0` 옵션을 주게 되면, 0초 안에 종료가 안된 프로세스를 강제로 `sigkill`을 할 수 있게 됩니다.


### 2. 컨테이너 접속

```bash
# 컨테이너 터미널 접속
$docker exec -it [컨테이너명] [CMD 명령어]

# 종료
$exit
```
* 위 명령어를 통하여 컨테이너 내부 터미널에 접속이 가능합니다.
* _위 명령어로 접속하는 방식은 ssh와 같은 네트워크 접속 방식이 아닌 프로세스에 직접 올라타는 방식입니다._

```bash
# 예시 1
$docker exec -it nginx8888 bash 

# 예시 2
$docker exec ng8888 echo "Hello"
Hello
```
* 일반적으로 -it 옵션 사용 시에는 명령어에 `Shell Type`을 호출합니다.
* `-it` 옵션이 없을 경우에는 바로 컨테이너 내부에서 명령어기 실행됩니다.

</br>

### 3. 컨테이너-호스트 파일 전송

```bash
$docker cp [원본 대상 파일 및 폴더] [목적 대상 파일 및 폴더]
```
* 호스트의 경로일 경우에는 일반적인 `절대경로`를 입력하면 되며, 컨테이너는 `[컨테이너명 or ID]:[절대 경로]`를 입력하면 됩니다.

```bash
# 예시1 (현재 경로의 test 파일을 ng8888 컨테이너의 루트 디렉터리로 복제합니다.)
docker cp test.txt ng8888:/ # 호스트 -> 컨테이너

# 예시2 (ng8888 컨테이너의 파일을 호스트로 복제합니다.)
docker cp ng8888:/test.txt test2.txt # 컨테이너 -> 호스트
```
